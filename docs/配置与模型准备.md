# 配置与模型准备

这份文档说明 `materials-demo-teaching/.env` 中各字段的作用，以及 MatterGen / MatterSim 模型与权重的准备方式。

## 1. 配置文件来源

本项目启动时会自动读取根目录下的 `.env`。

建议做法：

1. 先复制模板：

```bash
cp .env.example .env
```

2. 如果已经有可复用的现成环境，例如：

- `material-agent`
- `mcp`
- `agent-sdk-demos/chat-demo`

优先复用这些环境中已经验证过的路径，而不是重新猜测。

3. 首次配置时，建议先准备下面这些命令行工具：

- `python3 --version`
- `node -v`
- `npm -v`
- `which python`
- `which mattergen-generate`
- `find /some/root -name 'mattersim-v1.0.0-1M.pth'`

这些命令通常足以帮助你填完 `.env` 中的路径项。

如果你希望用户直接一条命令创建本项目主环境，推荐：

```bash
conda env create -f environment.yml
conda activate materials-demo-teaching
```

如果你已经激活了这个 conda 环境，再执行：

```bash
bash scripts/bootstrap.sh
```

它会：

- 把后端依赖同步安装到当前已激活的 conda 环境
- 安装 `frontend-next` 的前端依赖
- 自动复制 `.env.example -> .env`（如果 `.env` 还不存在）

说明：

- 当前项目主入口统一收口到 conda 环境
- 默认情况下只需要手填一个 Python：`DEMO_BACKEND_PYTHON`
- 推荐额外准备 MatterGen 和 MatterSim 两套外部环境

建议把 `DEMO_BACKEND_PYTHON` 填成：

```bash
/abs/path/to/conda/envs/materials-demo-teaching/bin/python
```

## 2. `.env` 字段说明

### 2.1 `MP_API_KEY`

Materials Project API key。

用途：

- 给 `materials-project` MCP server 调用真实 Materials Project 数据库。

没有这个 key 时：

- `materials-project` MCP 启动后实际检索会失败。

### 2.2 `DEMO_BACKEND_PYTHON`

本项目后端使用的 Python，通常应指向：

```bash
/abs/path/to/conda/envs/materials-demo-teaching/bin/python
```

用途：

- 跑 FastAPI
- 跑 LangGraph 工作流
- 调用本项目的 MCP HTTP client
- 默认也会被 `materials-project` MCP 和 `material-agent-core` MCP 继承复用

推荐填写方式：

```bash
cd materials-demo-teaching
pwd
```

假设输出是：

```bash
/home/you/projects/materials-demo-teaching
```

那么填写：

```bash
DEMO_BACKEND_PYTHON=/home/you/miniconda3/envs/materials-demo-teaching/bin/python
```

### 2.3 `MATERIALS_PROJECT_MCP_PYTHON`

启动 `materials-project` MCP server 使用的 Python。

默认情况下不需要填写。

启动脚本会按这个顺序找：

```bash
MATERIALS_PROJECT_MCP_PYTHON
DEMO_BACKEND_PYTHON
当前 shell 的 python
```

只有你想给 `materials-project` 单独拆环境时，才需要显式设置它。

如果显式设置，这个 Python 至少要能 import：

- `mcp`
- `mp_api`
- `pymatgen`

### 2.4 `MATERIAL_AGENT_CORE_MCP_PYTHON`

启动 `material-agent-core` MCP server 使用的 Python。

默认情况下也不需要填写。

启动脚本会按这个顺序找：

```bash
MATERIAL_AGENT_CORE_MCP_PYTHON
DEMO_BACKEND_PYTHON
当前 shell 的 python
```

只有你想给 `material-agent-core` 单独拆环境时，才需要显式设置它。

如果显式设置，这个 Python 至少要能 import：

- `mcp`
- `material_agent_mcp.server`

### 2.5 `MATERIAL_AGENT_REPO_ROOT`

外部 `material-agent` 仓库根目录。

要求：

- 目录存在
- 里面应包含 `material_agent/` 包

用途：

- `material-agent-core` MCP 会复用这个仓库里的 adapter
- 运行产物默认也会写到这个仓库下的 `runs/`

推荐填写方式：

```bash
cd /path/to/material-agent
pwd
```

### 2.6 `MATTERGEN_GENERATE_BIN`

`mattergen-generate` 可执行文件路径。

常见示例：

```bash
/abs/path/to/mattergen-env/bin/mattergen-generate
```

要求：

- 文件存在
- 有执行权限

自检：

```bash
/abs/path/to/mattergen-generate --help
```

推荐查找方式：

```bash
conda activate mattergen
which mattergen-generate
```

### 2.7 `MATTERSIM_PYTHON`

能够 import `mattersim` 的 Python。

常见示例：

```bash
/abs/path/to/mattersim-env/bin/python
```

自检：

```bash
/abs/path/to/python -c "import mattersim; print('ok')"
```

推荐查找方式：

```bash
conda activate mattersim
which python
```

### 2.8 `MATTERSIM_LOAD_PATH`

MatterSim 的 checkpoint 文件路径，通常是 `.pth`。

常见示例：

```bash
/abs/path/to/material-agent/agent_models/mattersim/pretrained_models/mattersim-v1.0.0-1M.pth
```

要求：

- 文件真实存在
- 启动脚本会直接检查它

推荐查找方式：

```bash
find /your/model/root -name 'mattersim-v1.0.0-1M.pth'
```

### 2.9 `MATTERSIM_DEVICE`

通常用：

- `cuda`
- `cpu`

如果机器没有 GPU，必须改成 `cpu`。

### 2.10 `LLM_ROUTER_*`

这组字段控制两件事：

- prompt 参数解析时，是否优先使用 LLM 提取 `formula / num_samples / relax`
- LangGraph 的 `decide_next_step` 节点是否用 LLM 决策

```bash
LLM_ROUTER_BASE_URL=
LLM_ROUTER_API_KEY=
LLM_ROUTER_MODEL=
LLM_ROUTER_TIMEOUT_SECONDS=30
```

说明：

- 这是 OpenAI 兼容接口
- 三个核心字段都留空时，系统自动回退到本地规则解析和内置规则路由
- 这个 LLM 不参与材料生成本身，只负责：
  - 从自然语言 prompt 中提取结构化运行参数
  - 判断“要不要检索 / 生成 / 评估”

## 3. MatterGen 模型准备

本项目不直接管理 MatterGen checkpoint，而是复用外部 `material-agent` 及其 MatterGen 环境。

### 3.1 推荐路径

推荐直接沿用 `material-agent` 里已验证过的 MatterGen 环境：

- 可执行文件：`MATTERGEN_GENERATE_BIN`
- HF cache：如果你在外部环境里配置了 `HF_HOME`，建议继续复用

### 3.2 在线下载

MatterGen 官方仓库与模型：

- GitHub: <https://github.com/microsoft/mattergen>
- Hugging Face: <https://huggingface.co/microsoft/mattergen>

建议本地路径：

```text
/abs/path/to/material-agent/agent_models/mattergen
```

对应 `.env`：

```bash
MATTERGEN_GENERATE_BIN=/abs/path/to/mattergen-env/bin/mattergen-generate
```

如果本地没有对应 checkpoint，MatterGen 可能会尝试从 Hugging Face 下载。

### 3.3 离线/半离线准备

如果服务器不能联网，建议提前在可联网环境准备：

1. 拉取或下载需要的 MatterGen checkpoints
2. 放到 `material-agent/agent_models/mattergen/checkpoints/` 或你的既有缓存目录
3. 确保 `mattergen-generate` 在当前环境里可直接加载它们

如果你使用的是 `material-agent` 当前已验证的 MatterGen 环境，最稳妥的方式通常是直接复用那套环境和缓存，不要重新构造。

## 4. MatterSim 模型准备

本项目当前通过 `MATTERSIM_PYTHON + MATTERSIM_LOAD_PATH` 调用 MatterSim。

### 4.1 推荐方式

直接复用 `material-agent` 已准备好的：

- MatterSim Python 环境
- `agent_models/mattersim/pretrained_models/*.pth`

### 4.2 权重来源

官方仓库：

- <https://github.com/microsoft/mattersim>

建议本地路径：

```text
/abs/path/to/material-agent/agent_models/mattersim
```

常用 checkpoint 文件名是：

```text
mattersim-v1.0.0-1M.pth
```

### 4.3 放置位置建议

推荐把 `.pth` 放在外部 `material-agent` 仓库中：

```text
/abs/path/to/material-agent/agent_models/mattersim/pretrained_models/
```

然后在 `.env` 里把 `MATTERSIM_LOAD_PATH` 指到这个文件。

对应 `.env` 推荐写法：

```bash
MATTERSIM_PYTHON=/abs/path/to/mattersim-env/bin/python
MATTERSIM_LOAD_PATH=/abs/path/to/material-agent/agent_models/mattersim/pretrained_models/mattersim-v1.0.0-1M.pth
```

## 6. 推荐自检顺序

在启动系统前，建议按下面顺序检查。

如果你是第一次下载这个仓库，推荐把顺序理解成：

1. 装后端 Python 依赖
2. 创建并激活本项目 conda 环境
3. 同步两个 MCP server 依赖到这个 conda 环境
4. 装前端 npm 依赖
5. 填 `.env`
6. 检查路径
7. 再启动服务

### 6.1 检查路径

```bash
ls -l "$MATERIAL_AGENT_REPO_ROOT"
ls -l "$MATTERGEN_GENERATE_BIN"
ls -l "$MATTERSIM_PYTHON"
ls -l "$MATTERSIM_LOAD_PATH"
```

### 6.2 检查可执行

```bash
"$MATTERGEN_GENERATE_BIN" --help
"$MATTERSIM_PYTHON" -c "import mattersim; print('mattersim ok')"
```

### 6.3 启动三套服务

```bash
bash scripts/start_materials_project.sh
bash scripts/start_material_agent_core.sh
bash scripts/start_demo_backend.sh
```

### 6.4 检查健康状态

```bash
curl http://127.0.0.1:18018/api/health
curl http://127.0.0.1:18018/api/config
```

### 6.5 跑 MCP 端到端检查

```bash
python3 scripts/run_end_to_end_checks.py
```

输出报告会写到：

```text
workdir/test-results/mcp-e2e-results.json
```

## 7. 常见问题

### 7.1 `MATTERGEN_GENERATE_BIN` 明明存在，但启动时报错

优先检查：

- 是否有执行权限
- 是否是当前环境中真实可运行的可执行文件
- 所在 conda/venv 是否完整

### 7.2 `MATTERSIM_LOAD_PATH` 正确，但评估时报错

优先检查：

- `MATTERSIM_PYTHON` 是否真能 import `mattersim`
- `.pth` 文件和当前 MatterSim 代码版本是否兼容
- `MATTERSIM_DEVICE` 是否与机器 GPU/驱动状态一致

### 7.3 LLM Router 没开时是不是不能跑

不是。

`LLM_ROUTER_BASE_URL / API_KEY / MODEL` 全留空时：

- 工作流仍然能跑
- 只是不走 LLM 参数解析和 LLM 路由决策
- 会改用本地规则补齐 `formula / num_samples / relax`
- 并用内置规则判断是否执行检索 / 生成 / 评估

### 7.4 为什么建议用绝对路径

因为这个项目会分别启动多个进程：

- FastAPI 后端
- Materials Project MCP
- Material Agent Core MCP

绝对路径最稳，能避免不同工作目录下解析错路径。
